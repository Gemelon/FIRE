Detailed Description

Represents one complete file record persisted in the FIRE database.

Each FIREDbRecord corresponds to a single source file that has been scanned and catalogued by the FIRE pipeline. It stores file identification information, paths, and all metadata collected from the file.

A FIREDbRecord is the primary domain model for FIRE. It typically progresses through the three-step pipeline as follows:

  1. collect: SourceFilePath is set, and FileMetaDatas are populated from configured metadata sources.
  2. generate: TargetFilePath is computed by evaluating path templates with resolved metadata values.
  3. execute: The file operation (Copy, Move, or Link) is performed from SourceFilePath to TargetFilePath.

The VolumeSerialNumber and FileId are used on Windows/NTFS systems to detect hard links and duplicates, avoiding unnecessary processing of the same physical file.

Creating a record after file collection:

var record = new FIREDbRecord
{
SourceFilePath = @"D:\Photos\IMG_1234.jpg",
VolumeSerialNumber = volumeSerialNumber,
FileId = fileId,
FileMetaDatas = new List<FIREFileMetaData>
{
new() { Key = "Make", Value = "Apple", DataSource = "EXIFTOOL" },
new() { Key = "Model", Value = "iPhone 15 Pro", DataSource = "EXIFTOOL" }
}
};

◆ AssignedCounterValue

long? FIRE.FIREDbRecord.AssignedCounterValue
getset

Gets or sets the counter value that was assigned to this record during the last generate phase, or null if no counter placeholder is used in the file-name template.

When a file-name template contains a {Counter:Dx} placeholder, the numeric counter value allocated by FIREDatabase.GetNextCounterValue is stored here. Before each generate run the per-scope counter states are reset to the maximum AssignedCounterValue found among ProcessingStatus.Executed records for the same scope, so that repeated Generate runs do not keep incrementing the global counter beyond what has been committed to the file system.

Defaults to null for records that were collected before this field was introduced and for records whose template contains no counter placeholder.

◆ ExcludedFromExecute

bool FIRE.FIREDbRecord.ExcludedFromExecute = false
getset

Gets or sets whether this file should be excluded from the Execute phase.

When set to true, this file will be skipped during execute operations, preventing the file operation (copy/move/link) from being performed. This is useful when the user reviews generated paths and decides to exclude specific files from being physically moved or copied.

Defaults to false (file will be processed normally).

Note: If ExcludedFromGenerate is true and no target path has been generated, this file will also be implicitly excluded from Execute regardless of this flag's value.

◆ ExcludedFromGenerate

bool FIRE.FIREDbRecord.ExcludedFromGenerate = false
getset

Gets or sets whether this file should be excluded from the Generate phase.

When set to true, this file will be skipped during generate operations, preventing target path generation. This is useful when the user inspects collected files and decides that certain files should not be reorganized or processed further.

Defaults to false (file will be processed normally).

This flag is independent of ProcessingStatus, allowing users to exclude files at any point in the workflow, including files that have already been processed.

◆ FileId

byte? [] FIRE.FIREDbRecord.FileId
getset

Gets or sets the binary file identifier from the NTFS file system, if available.

This 16-byte identifier is unique per file on the NTFS volume and persists even if the file is renamed or moved. It is obtained via the Windows API's GetFileInformationByHandleEx function. This field is null on non-NTFS systems or if the API call fails.

File IDs are useful for detecting hard links to the same physical file, which is important for avoiding duplicate processing.

◆ FileIdHash

string? FIRE.FIREDbRecord.FileIdHash
getset

Gets or sets the cryptographic hash of the VolumeSerialNumber and FileId combination.

This field stores a SHA256 hash computed from the VolumeSerialNumber and FileId to provide a fast, non-reversible unique identifier for duplicate detection.

The hash is computed once during file collection and stored persistently in the database. This allows efficient duplicate detection without comparing binary FileId arrays or relying on the in-memory index.

This field is null if the file lacks a valid FileId (e.g., on non-NTFS systems or if the API call failed).

Gets or sets the file metadata entries associated with this record.

This collection is populated during the collect phase by querying all configured metadata sources (EXIFTOOL, FILEINFO, etc.) for the file. The collection is persisted to the database as child rows in a one-to-many relationship. Each entry in this list corresponds to a single keyword resolved from the FIRE configuration.

◆ SourceFileExists

bool FIRE.FIREDbRecord.SourceFileExists = true
getset

Gets or sets whether the source file still exists at SourceFilePath.

This field is updated when the user explicitly runs a source-verification command. It allows FIRE to track files that have been moved or deleted from their source location after being catalogued, without removing them from the database.

Defaults to true when the file is first collected. Setting this to false does not prevent the file from being processed; it merely records that the source location is no longer accessible.

Gets or sets the computed target file path, as determined during the generate phase.

This path is calculated by evaluating the SortingPatern and FileNamePatern configuration templates with resolved metadata values.
