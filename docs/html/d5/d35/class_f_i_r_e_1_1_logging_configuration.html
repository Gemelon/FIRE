Detailed Description

Configures the FIRE logging subsystem.

Activation: Logging is active only when this section is present in the YAML configuration. If the Logging key is absent, no log files are created.

File naming: One file per calendar day and per stage is created: {LogFileName}.col.{yyyyMMdd}.md (collect), {LogFileName}.gen.{yyyyMMdd}.md (generate), {LogFileName}.exe.{yyyyMMdd}.md (execute).

Rotation: When a log file exceeds MaxFileSizeBytes (default 10 MB), a new numbered segment is started automatically: {LogFileName}.col.{yyyyMMdd}.1.md, .2.md, … A single 10 MB limit keeps individual files easily openable in any text editor.

Retention: On every catalog run, log files older than MaxAgeDays days (default 30) are deleted from the log directory. 30 days covers a reasonable audit window without consuming excessive disk space; adjust downwards for high-volume environments.

◆ MaxAgeDays

int FIRE.LoggingConfiguration.MaxAgeDays = 30
getset

Gets or sets the number of days to retain log files.

Log files older than this value are deleted at the start of every catalog run. Defaults to 30 days. Set to 0 to disable automatic deletion. Recommended range: 7–90 days, depending on disk space and audit requirements.

◆ MaxFileSizeBytes

long FIRE.LoggingConfiguration.MaxFileSizeBytes = 10 * 1024 * 1024
getset

Gets or sets the maximum log file size in bytes before a new segment is started.

Defaults to 10 MB (10,485,760 bytes). Files above this threshold are rotated by appending a numeric suffix before the .md extension. Recommended range: 1 MB–50 MB. Very large files become slow to open in editors.
