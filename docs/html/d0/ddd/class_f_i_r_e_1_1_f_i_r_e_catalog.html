Detailed Description

Orchestrates the three-step FIRE processing pipeline: collect, generate, and execute.

FIRECatalog is the main orchestrator that drives metadata collection from files, generates target directory and file names using path templates, and executes file operations (Copy, Move, or Link). It integrates the configuration, database, and metadata sources to implement the complete file processing workflow.

Three-Step Workflow:

  1. Collect: CollectFiles recursively scans all configured root directories, creates file records for each file, and populates metadata from configured sources.
  2. Generate: GenerateTargetPaths computes output directory and file name for each record by parsing path templates with resolved metadata values.
  3. Execute: ExecuteFileOperations performs the configured file operation (Copy, Move, or Link) from source to target path.

Windows File Identification: FIRECatalog uses Windows API calls (GetFileInformationByHandleEx) to retrieve volume serial numbers and file IDs, which enable detection of hard links and files on the same physical volume. This is done on Windows/NTFS systems only.

Extensibility: The metadata extraction system is extensible via MetadataSourceRegistry. Custom metadata sources can be registered to support additional file formats or sources.

Resource Management: This class implements IDisposable to properly clean up the database and metadata sources. Always dispose of this instance when done.

Using FIRECatalog for the complete pipeline:

var config = FIREConfigration.Load("Configuration.yaml");
config.EnsureSupportedConfigurationVersion();
var dbPath = Path.Combine(config.DataBasePath, config.DataBaseFileName);
using var database = new FIREDatabase(dbPath);
using (var catalog = new FIRECatalog(config, database))
{
// Step 1: Collect metadata
catalog.CollectFiles(path => Console.WriteLine($"Collecting: {path}"));
// Step 2: Generate target paths
catalog.GenerateTargetPaths(path => Console.WriteLine($"Generating: {path}"));
// Step 3: Execute file operations
catalog.ExecuteFileOperations(path => Console.WriteLine($"Processing: {path}"));
}

◆ CollectFiles()

void FIRE.FIRECatalog.CollectFiles ( Action< string >? progressCallback = null)
inline

Step 1: Collects all files and their metadata from configured root directories.

Parameters
progressCallbackOptional callback invoked for each file being processed. The callback receives the file path. Use this to report progress in a UI or log file.

This method:

  1. Clears any existing records from the database.
  2. Recursively scans all paths in FIREConfigration.FilesRootPath.
  3. For each file matching a configured file extension:
    • Retrieves file ID information from the OS.
    • Queries metadata from all configured sources and keywords.
    • Creates a FIREDbRecord and adds it to the database.
  4. Saves all records to the database when complete.

Errors during file access or metadata extraction are logged but do not stop the pipeline.

ObjectDisposedExceptionThrown if this instance has been disposed.

string? FIRE.FIRECatalog.DiagnoseGeneration ( string sourceFilePath)

Generates a detailed diagnostic report for path generation of a specific source file and writes it to a Markdown file.

Parameters
sourceFilePathAbsolute path of the source file to diagnose.
Returns
Absolute path of the generated diagnostic Markdown file, or null if the file is not in the database.

This method does not modify the database or any records. It performs a read-only analysis of how the target path would be generated for the given source file, instrumenting each step of the template resolution, string replacement, and counter allocation process.

The diagnostic report includes:

  • Database record details (VolumeSerialNumber, FileId, Status, Classification)
  • Extension configuration lookup and patterns
  • Raw metadata values stored in the database
  • Step-by-step placeholder resolution for sorting and filename patterns
  • Applied string replacements
  • Counter value (if applicable)
  • Final target directory, filename, and full path
  • Warnings for missing metadata, failed datetime parsing, or "Unknown" fallbacks

The report is written to {LogFilePath}/Diagnose_{timestamp}_{filename}.md. If logging is not configured, the report is written to the current directory.

Step 3: Executes the configured file operation (Copy, Move, or Link) for all records.

Parameters
progressCallbackOptional callback invoked for each file being processed. The callback receives the target path.

This method iterates over all records and performs the configured file operation:

  • Skips records with null or invalid paths or files that no longer exist.
  • Looks up the file extension configuration.
  • Retrieves the action (Copy, Move, or Link) using extension-specific overrides if available.
  • Calls ExecuteAction to perform the operation.

The operation creates all necessary output directories and handles errors gracefully. All changes are persisted to the database when complete.

◆ GenerateTargetPaths()

void FIRE.FIRECatalog.GenerateTargetPaths ( Action< string >? progressCallback = null)
inline

Step 2: Generates target file paths for all collected file records.

Parameters
progressCallbackOptional callback invoked for each file being processed. The callback receives the generated target path when available.

This method iterates over all records in the database and computes the target directory and file name by:

  1. Looking up the file extension configuration.
  2. Retrieving the sorting and file name patterns (using extension-specific overrides if available).
  3. Resolving metadata placeholders in the patterns using ParseTemplate.
  4. Applying global string replacements from the configuration.
  5. Constructing the final target path.

The target path is set in the FIREDbRecord.TargetFilePath property. If the patterns or resolution fails, the target path remains null.

ObjectDisposedExceptionThrown if this instance has been disposed.

◆ GetAllAvailableMetadata()

List<(string Source, string Key, string Value)> FIRE.FIRECatalog.GetAllAvailableMetadata ( string filePath)
inline

Retrieves all available metadata for a single file from all registered metadata sources.

Parameters
filePathAbsolute path to the file for which metadata should be retrieved.
Returns
A list of tuples containing the source name, metadata key, and metadata value for each available metadata entry. This list shows all metadata that can be extracted from the file and used in the YAML configuration file.

Purpose: This method is useful for discovering which metadata keys are available for a specific file type and can be used in the YAML configuration. It queries all registered metadata sources (FILEINFO, EXIFTOOL, etc.) and returns every key-value pair found.

Return Format: Each tuple in the returned list contains:

  • Source: Name of the metadata source (e.g., "FILEINFO", "EXIFTOOL")
  • Key: Metadata key/tag name (e.g., "Make", "Model", "DateTimeOriginal")
  • Value: The extracted metadata value as a string

Usage Example: Use this method to explore what metadata is available in your files before configuring keywords in the YAML configuration. The returned keys can be directly used in the AvailableKeyWords section of your configuration.

Error Handling: If the file does not exist or if metadata extraction fails for a particular source, that source will not contribute entries to the result list. The method continues processing other sources and does not throw exceptions.

Exceptions
ObjectDisposedExceptionThrown if this instance has been disposed.

Discovering available metadata for a file:

var config = FIREConfigration.Load("Configuration.yaml");
var dbPath = Path.Combine(config.DataBasePath, config.DataBaseFileName);
using var database = new FIREDatabase(dbPath);
using var catalog = new FIRECatalog(config, database);
var metadata = catalog.GetAllAvailableMetadata(@"D:\Photos\IMG_1234.jpg");
foreach (var (source, key, value) in metadata)
{
Console.WriteLine($"[{source}] {key}: {value}");
}

Retrieves all available metadata for a single file and writes it to a Markdown file.

Parameters
filePathAbsolute path to the file for which metadata should be retrieved.
outputPathOptional output path for the Markdown file. If not specified, the output file will be created in the same directory as the source file with the same name but a .md extension.

Purpose: This method extracts all available metadata from the specified file and creates a well-formatted Markdown report. This report can be used to document which metadata keys are available for configuration in the YAML file.

Output Format: The generated Markdown file contains:

  • File information (path, name, size, timestamps)
  • Metadata grouped by source (FILEINFO, EXIFTOOL)
  • Tables with Key and Value columns for each source
  • Summary statistics

Error Handling: If the file does not exist or metadata cannot be extracted, an appropriate message is written to the Markdown file. The method does not throw exceptions for metadata extraction failures.

Exceptions
ObjectDisposedExceptionThrown if this instance has been disposed.
IOExceptionThrown if the output file cannot be written.

Creating a metadata report:

var config = FIREConfigration.Load("Configuration.yaml");

// Creates "IMG_1234.md" in the same directory

◆ FallbackDateTime

DateTime FIRE.FIRECatalog.FallbackDateTime = DateTime.Now
getset

Gets or sets the fallback DateTime to use when parsed date values are implausible. Defaults to DateTime.Now.

A date is considered implausible if its year is less than 1900 or more than 10 years in the future. When an implausible date is detected during metadata processing or path generation, this fallback value will be used instead and a warning will be logged.

Applications can override this property to use a specific date for reproducible results, for example during testing or when processing archived collections with known date ranges.
