enum FIRE.FileClassification

Categorizes files by their role in the collection.

This enum allows FIRE to distinguish between different file types during processing. Regular files are processed normally through the metadata extraction and path generation pipeline. Sidecar files inherit the target path from their associated primary file (only the extension differs).

This enumeration distinguishes between primary files that are processed through the normal metadata extraction pipeline and auxiliary sidecar files that inherit path generation from their associated primary file.

During the collection phase, sidecar files are automatically detected based on the SidecarFileExtensions configuration and added to the database with SidecarFile classification. In the generate phase, they inherit the target directory and base filename from their primary file. In the execute phase, they use the global action setting.

Enumerator
RegularFile 

A regular primary file processed through the full FIRE pipeline. This is the default classification for all collected files.

Regular files (e.g., .jpg, .mp4, .dng) undergo metadata extraction, template-based path generation, and file operations according to their extension-specific configuration.

SidecarFile 

A sidecar file (e.g., .xmp, .pp3) that follows its primary file.

Sidecar files contain auxiliary metadata or processing instructions and are typically processed alongside their primary file.

Sidecar files inherit the target path from their primary file during the generate phase and use the global action during the execute phase. They are detected automatically when listed in the primary file's SidecarFileExtensions configuration.

◆ ProcessingStatus

enum FIRE.ProcessingStatus

Specifies the processing status of a file record in the FIRE pipeline.

This enumeration tracks the progress of a file through the three-step FIRE workflow: collect → generate → execute.

The status progression is linear:

  • NotProcessed: File collected, awaiting path generation
  • PathGenerated: Target path computed, awaiting execution
  • Executed: File operation completed successfully

This allows FIRE to support incremental workflows where only new or unprocessed files are affected by subsequent generate and execute operations.

Enumerator
NotProcessed 

File has been collected but no target path has been generated yet. This is the default state for newly added files.

Files in this state will be processed by the next generate operation.

PathGenerated 

Target path has been generated but the file operation has not been executed.

Files in this state will be processed by the next execute operation. The FIREDbRecord.TargetFilePath field contains the computed path.

Executed 

File operation (copy/move/link) has been successfully completed.

Files in this state are excluded from subsequent generate and execute operations unless explicitly reprocessed or the database is cleared.
